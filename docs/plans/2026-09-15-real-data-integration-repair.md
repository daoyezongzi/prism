# 真实数据接入故障修复计划

## 目标

修复真实数据模式下的四条用户路径：AI 金融对话、股票研判、持仓体检、评测套件。修复必须保持真实数据与离线样例的边界，不以样例或大模型推断补写缺失的金融字段。

## 已确认事实

1. 扶摇真实行情可以返回 300750 的价格 329.63，但当前行情契约不提供 PE(TTM)、PB、ROE、估值分位数，因此不能单独生成估值结论。
2. 当前问财凭证的九项 Skill 实测为 7 项成功、2 项 HTTP 401；失败项是 `hithink-market-query` 与 `hithink-finance-query`。这属于凭证权限/服务端能力边界，不应伪造指标。
3. 持仓刷新把行业字段查询错误地路由到 `COMPANY_DATA`，而当前凭证对 `INDUSTRY_DATA` 可用；这是持仓体检失败的代码根因。
4. Python 评测命令本身通过，但 LIVE API 由于通用的 Fixture 拒绝闸门返回 409。评测套件是离线语义回归，不应被当作实时金融研究结果。
5. 对话在模型只返回文字、不返回工具调用时直接失败；可对可解析证券标识执行确定性工具兜底，但不能绕过真实工具校验。

## 方案比较

| 方案 | 做法 | 优点 | 风险 |
| --- | --- | --- | --- |
| A：最小修复 | 修正行业 Skill、增加对话兜底、评测单独放行、前端改文案 | 改动小、回归面窄 | 单个问财 Skill 失败仍可能污染其他能力状态 |
| B：能力矩阵 | 按 Skill/操作记录可用性，查询失败只隔离对应能力，并增加财务字段映射 | 与真实外部权限一致，能保留部分可用能力 | 状态契约和测试改动较多 |

## 选定方案

采用 A+B 的窄化组合：引入向后兼容的问财能力粒度状态，同时只实现当前已有真实服务契约能证明的行业与财务字段映射；不引入未经验证的替代行情源，不把评测结果混入 LIVE 研究结果。

## 实施范围

1. Runtime：增加按能力记录/读取问财探针结果；单个 Skill 失败不再清空其他已验证能力。
2. Portfolio：将股票行业补全改为 `INDUSTRY_DATA`，保留缺失字段的硬闸门。
3. Live quote：在财务 Skill 可用时使用确定性列名映射补全 PE/PB/ROE/估值分位数；失败时返回可审计的复核状态。
4. Copilot：模型未调用工具但消息中存在可解析证券标识时，执行真实行情工具并以工具结果生成回复；无法解析时继续安全拒绝。
5. Evaluation：允许 LIVE 页面运行明确标注为 `OFFLINE_FIXTURE` 的回归套件，继续拒绝其他 Fixture 研究服务。
6. Frontend：隐藏内部枚举式状态的主展示，改成用户可理解的实时/待补全/离线回归文案，保留必要的审计细节。
7. Tests/docs：增加针对四条失败路径的回归测试，运行原有单元/集成测试与真实只读探针，更新 `LOG.md`/`TODO.md`。

## 验证标准

- 300750 真实行情仍标记为非合成且保留观察时间；当前 401 权限下不生成伪估值。
- 股票持仓使用当前可用的行业 Skill 后能够完成刷新与体检；行业 Skill 不可用时仍进入复核而非静默使用样例。
- 对话 content-only 响应在可解析证券标识下能产生工具事件和真实结果；教育类问题不触发工具。
- LIVE 评测 API 返回离线回归标识，其他 Fixture API 仍返回 LIVE 拒绝。
- 主工作树保持干净；修复工作树提交但不自动推送。
